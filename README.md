# Perkly — כרטיסי נאמנות דיגיטליים (גרסה 0.7)

> **השקה:** ראו [`docs/LAUNCH.md`](docs/LAUNCH.md) לרשימת השלבים שנשארו.

מערכת לכרטיסי ניקוב דיגיטליים לעסקים: הלקוח אוסף חותמות בכל רכישה ומקבל הטבה.
רצה על Cloudflare Workers עם מסד נתונים Cloudflare D1. אין יותר תלות ב־ChatGPT Sites.

### כללים שחשוב לדעת
- **שינוי מספר החותמות** חל על כרטיסים חדשים. כרטיס קיים שומר על המספר שלו עד המימוש הבא, ואז עובר למספר החדש.
- **תיקון יתרה** (+1/−1) רק לבעלים, עם סיבה חובה. נשמר בהיסטוריה. היסטוריה לא נמחקת.
- **סריקת QR לא מוסיפה חותמת.** העובד תמיד מאשר בלחיצה, והשרת מאשר בחזרה.
- **בקשה חוזרת** (למשל אחרי ניתוק רשת) נשלחת עם אותו מזהה ולא נספרת פעמיים.
- **קישור כרטיס** הוא סוד: רק ה־hash שלו נשמר במסד. "קישור חדש" מבטל את הקודם.
- **מצבי הטבה**: במצב צבירה, חותמות שעוברות את היעד נשמרות כמתנה (גם כמה בבת אחת), והסבב הבא משתמש בתוכנית הנוכחית.
  מימוש משתמש במתנה השמורה הוותיקה ביותר שעדיין בתוקף. שינוי תוקף חל רק על מתנות חדשות. מעבר ממימוש מיד לצבירה הופך כרטיסים מלאים למתנה שמורה.
- **סניפים**: לקוחות וכרטיסים משותפים לכל הסניפים. ברגע שיש לעסק סניף אחד לפחות, כל חותמת/מימוש/תיקון חייבים סניף.
  עובד ששויך לסניף תמיד נרשם בסניף שלו. סגירת סניף שומרת את ההיסטוריה; עובדים שלו נחסמים עד שמעבירים אותם.
- **עיצוב** נשמר כטיוטה עד שלוחצים "פרסום". כל פרסום הוא גרסה חדשה שנשמרת לתמיד. עיצוב אף פעם לא משנה חותמות או זכאות.
  פרסום נחסם אם הטקסט לא קריא (ניגודיות נמוכה מ־3:1), אם חסר טקסט באחת השפות, או אם חסרה תמונה שנבחרה.
- **תמונות** מוקטנות בדפדפן לפני העלאה (עד 800KB) ונשמרות במסד D1. רק PNG, JPG ו־WebP; סוג וגודל נבדקים בשרת. SVG לא מתקבל.

## הפעלה מקומית (Windows CMD)

דרוש Node.js 22.13 ומעלה. כל פקודה מקלידים בחלון CMD בתוך תיקיית הפרויקט.

```
cd %USERPROFILE%\Downloads\Perkly_v0.2
npm install
npm run db:migrate:local
npm run build
npm run preview
```

אחרי `npm run preview` אמורה להופיע השורה `Ready on http://localhost:8787`.
פותחים את הכתובת הזו בדפדפן **באותו מחשב**. זו כתובת מקומית בלבד, היא לא נגישה מהאינטרנט.

לבדיקות אוטומטיות: בחלון CMD שני, בזמן שהשרת רץ:
```
npm test
npm run test:api
```

הגדרות מקומיות אופציונליות: מעתיקים את `.env.example` לקובץ בשם `.dev.vars`.

> אם `npm install` נכשל ב־`ETIMEDOUT` — זו חסימת רשת (למשל רשת ארגונית/VPN), לא בעיה בפרויקט.
> נסו מרשת ביתית, או בקשו ממחלקת IT גישה ל־`registry.npmjs.org`. אל תבטלו בדיקות SSL.

## העלאה לאוויר (Cloudflare, דרך GitHub, בלי להתקין כלום)

הפריסה אוטומטית ב־GitHub Actions (`.github/workflows/deploy.yml`):
- כל עדכון ל־`main` מריץ את כל הבדיקות, ואם עברו, מעלה לסביבת **בדיקה** (`perkly-staging`).
- העלאה ל**ייצור** (`perkly`): בלשונית Actions לוחצים "Run workflow" ובוחרים production.
- מסדי הנתונים נוצרים אוטומטית בפעם הראשונה, והמיגרציות רצות לפני כל העלאה.

**הגדרה חד־פעמית (בדפדפן):**
1. ב־Cloudflare: My Profile → API Tokens → Create Token → תבנית **Edit Cloudflare Workers**.
   מוסיפים הרשאה: **Account → D1 → Edit**. יוצרים ומעתיקים את הטוקן.
2. ב־GitHub, במאגר: Settings → Secrets and variables → Actions → New repository secret:
   - `CLOUDFLARE_API_TOKEN` = הטוקן מהשלב הקודם (חובה).
   - `CLOUDFLARE_ACCOUNT_ID` = מזהה החשבון מלוח הבקרה של Cloudflare (מומלץ).
   - `PERKLY_SIGNUP_CODE` = קוד שרק בעלי עסקים שהזמנתם יקבלו (מומלץ, כדי שזרים לא יפתחו חשבונות).
   - `PERKLY_ADMIN_EMAILS` = האימייל שלכם, לדף `/admin` (אופציונלי).
3. אם זו הפעם הראשונה ב־Cloudflare Workers: נכנסים פעם אחת ל־Workers & Pages ובוחרים כתובת משנה (subdomain) ל־workers.dev.

הכתובת הציבורית מופיעה בסוף שלב "Deploy" ביומן של GitHub Actions.
**אף פעם לא להדביק טוקנים או סיסמאות בצ'אט או בקוד.**

### פריסה ידנית מהמחשב (חלופה)
`npx wrangler login`, ואז `node scripts/ci-prepare-d1.mjs staging`, `npm run db:migrate:staging`, `npm run deploy:staging`.

## מעבר מגרסת ChatGPT Sites

- הכניסה דרך ChatGPT הוסרה לגמרי. השרת מתעלם מכותרות `oai-authenticated-*`, כך שאי אפשר להתחזות בעזרתן.
- המיגרציה `0001` מוסיפה טבלאות ועמודות בלי למחוק נתונים, ממירה טלפונים קיימים לצורה האחידה ושומרת על קודי QR קיימים.
- עסקים שנוצרו ב־ChatGPT Sites שייכים למזהה משתמש של ChatGPT ולכן לא יופיעו לאף משתמש חדש.
  לא היו נתוני לקוחות אמיתיים בפיילוט. אם יש, צריך לייצא אותם מ־Sites ולשייך ידנית.

```
app/api/auth      הרשמה, כניסה, יציאה, קבלת הזמנה

app/api/join      הצטרפות עצמית של לקוחות (ציבורי, עם הגבלת קצב)
app/c/[secret]    כרטיס הלקוח (ציבורי, לפי קישור סודי)
app/join/[code]   טופס הצטרפות ללקוחות
app/invite/[token] הצטרפות עובד
app/admin         מנהל פלטפורמה (צפייה בלבד)
lib/server        סיסמאות, Session, הגבלת קצב
lib/phone.ts      כלל נרמול הטלפון
db/schema.ts      סכמת המסד; drizzle/ מיגרציות
worker/index.ts   נקודת הכניסה ל־Worker + כותרות אבטחה
tests/            בדיקות יחידה ובדיקות קבלה מול שרת רץ
```
